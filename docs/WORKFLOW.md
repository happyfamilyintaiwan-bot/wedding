# wedding 網站的工作模式（Zoe 2026-11-22 定；Alison 也照這個模式）

## 一句話

**子對話把各自的頁面做好，主對話當整體顧問，定期看整個網站給建議。**

```
主對話（整體顧問）
 ├─ 客戶：每個客戶一個子對話（成品喜帖，個資只在本機，不進 GitHub）
 ├─ 頁面：似顏繪／電子喜帖／紙本喜帖／結婚書約，各一個子對話
 ├─ 部落格：版型、呈現與 SEO（共用元件、內容規劃）一個子對話
 └─ 部落格：每個文章系列一個子對話（例：婚禮歌單、台灣人與外國人在台結婚）
```

## 各自負責什麼

| 對話 | 負責 | 不負責 |
|---|---|---|
| 主對話 | 看整個網站：定價、頁面之間的一致性、SEO 與 GA4 成效、優先順序；定期給建議、開新的子對話 | 不直接寫單篇文章、不做單一客戶 |
| 頁面子對話 | 自己那一頁的內容、版型、範本、FAQ | 改價格要通知主對話（價格會影響首頁、估價工具、全套方案） |
| 部落格版型子對話 | 文章共用元件、部落格首頁、SEO 規範、內容規劃 | 不寫單篇內容 |
| 文章系列子對話 | 該系列的每一篇（先給大綱，同意後才寫） | 新的共用元件請版型子對話做 |
| 客戶子對話 | 該客戶的喜帖、確認、交付、到期關閉 | 不改網站與範本（要改範本請電子喜帖子對話） |

## 共同規則

- 一個 PR 一件事，squash 合併，上線後讀回線上確認。
- 改價格要同時改：首頁方案卡、估價工具 JS、首頁 JSON-LD、`tools/build_pages.py`（外語頁改 `tools/intl_strings.py`、專案頁改 `tools/build_package.py`）。
- FAQ 和 JSON-LD 逐字一致；中文全形標點；不用 em dash、en dash。
- 部落格每篇的固定元素：封面圖、開頭 3 句話結論、步驟編號清單、比較或文件表格、重點框、懶人包圖；服務只放 2 處（文中情境卡片 1 張＋文末服務卡片 1 張）。
- 法規類文章以官方公告為主，附官方連結；不確定標「待確認」。
- 客人的個資（姓名、地址、賓客資料）只放在本機 `~/Sites/knittinghiyori/wedding-invites/`，不進任何 GitHub repo。
